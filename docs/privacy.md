# Privacidad y enlaces privados

Cada token se genera con `crypto.randomBytes(32)` y se persiste como SHA-256 hexadecimal. El enlace claro solo aparece una vez en la terminal que creó o rotó la credencial. Guardarlo en un gestor seguro y compartirlo por un canal privado. Un enlace puede reenviarse; el destinatario puede compartir el acceso.

La página y la ruta PDF comparan el token en el servidor. Tokens desconocidos, inactivos o revocados responden 404 genérico. Las respuestas privadas llevan `Cache-Control: private, no-store`, `X-Robots-Tag: noindex, nofollow, noarchive` y `Referrer-Policy: no-referrer`. El sitio completo arranca con indexación desactivada. Metadatos sociales son genéricos.

No incluir tokens en nombres de archivo, analítica, URLs externas, `NEXT_PUBLIC_*`, contenido versionado o mensajes de error. La app no integra analítica. El link a c3.com.sv está solo en el cierre general; no se transmite el token por referer. Next en desarrollo omite las solicitudes privadas de su log de consola. Vercel registra el `requestPath` real en sus logs de runtime; la aplicación no puede eliminar ese dato de los registros administrados por la plataforma. Restringir acceso y retención de dichos registros y no conectar un log drain sin redacción de rutas privadas. Vercel documenta el campo [requestPath](https://vercel.com/docs/logs/runtime); Next documenta el filtrado de solicitudes [solo en desarrollo](https://nextjs.org/docs/app/api-reference/config/next-config-js/logging).

Las páginas no envían fichas de otras compañías al navegador. Sin embargo, el repositorio GitHub actual es público y su JSON de destinatarios también puede leerse allí. Solo contiene nombres de borrador y campos vacíos; no agregar datos reales, hashes activos ni medios protegidos. Antes de activar experiencias privadas, mover las fichas y los medios a un origen privado. Las rutas personalizadas permanecen bloqueadas mientras no exista esa configuración aprobada.

Para crear una ficha, confirmar antes destinatario, edición y estado editorial. Después correr `npm run token:create -- --edition 2026 --recipient <id>` y registrar el enlace fuera de Git. Revocar con `npm run token:revoke -- --edition 2026 --recipient <id>`; rotar invalida el link previo. En despliegue serverless los JSON de credenciales son parte de la configuración del build; la revocación exige actualizar y redeplegar la configuración. Para revocación inmediata sin redeploy se necesitaría almacenamiento dinámico, fuera del alcance y costo inicial aprobados.
