# Auditoría y optimización — 25 de noviembre de 2026

Se conserva Next.js, React, CSS propio, las tipografías, colores y narrativa existentes. No se añadieron dependencias, empresas, cifras ni credenciales reales. No se implementaron funciones de compartir ni se ejecutó un despliegue.

## Rendimiento y experiencia

| Hallazgo | Impacto / esfuerzo | Cambio |
| --- | --- | --- |
| Las 13 escenas se montaban al inicio | Alto / medio | Se montan la actual, vecinas y saliente. Inicio: 13 → 2 escenas (85% menos); normalmente 3, máximo 4 durante un salto. El PDF conserva todas. |
| Pausa incompleta y oculta en móvil | Alto / bajo | Pausa global disponible en móvil; resuelve animaciones y contadores al estado final. Vecinas detenidas. |
| Escala de retrato aplicada en horizontal | Alto / bajo | Corregida la regla por ancho: Comenzar vuelve a quedar dentro del escenario en 844×390 y 640×360. |
| Progreso pequeño y controles superpuestos | Medio / bajo | Objetivos mínimos 24×24, tira desplazable y pausa separada de los controles editoriales. Gestos sobre controles no cambian de slide. |
| Recursos y esperas | Medio / bajo | Imágenes públicas responsivas mediante next/image; preparación limitada a escenas cercanas. Título de Somos36 inicia a 1.8 s en lugar de 5 s; texto a 2 s en lugar de 5.5 s. |
| Fuentes con subconjuntos innecesarios | Medio / bajo | CSS de fuentes: 34 → 8 declaraciones; 14,490 → 2,156 bytes de CSS fuente. No implica ese ahorro en descarga de fuentes: el navegador ya aplicaba unicode-range. |
| Navegación y foco | Medio / bajo | HUD oculto inerte, fragmentos malformados seguros y cambios de fragmento/restauración al volver compatibles con la escena visible. |

Se eliminaron envoltorios, propiedades de estado, alias CSS y exportaciones sin consumidores. Se reutilizan el motor, las escenas y los validadores existentes. No se añadió carga dinámica de módulos que pudiera dejar vacíos los saltos entre capítulos.

## Privacidad y empresas

Guía de incorporación: [configuración empresarial](company-configuration.md). Servidor y comandos leen el mismo archivo; no se duplica una experiencia por empresa. El archivo privado debe suministrarse al entorno de build de forma privada. File tracing explícito evita incluir todo el proyecto en el artefacto de servidor.

## PDF

La exportación final rechaza una edición/ficha no aprobada, filtra el contenido antes de renderizar y espera fuentes y decodificación de imágenes. Una imagen rota cancela la generación. Pruebas del render estático verifican 13 páginas generales y 14 privadas en 16:9.

La edición actual sigue en borrador: no se emitieron PDFs finales ni tokens reales. El hash de versión cubre JSON, no bytes de imágenes/estilos; tras reemplazarlos hay que regenerar el PDF. Ver [PDF](pdf.md).

## Validación realizada

- 30 pruebas unitarias aprobadas, incluidas credenciales con archivos temporales, filtros y autorización de medios.
- Compilación de producción aprobada sin advertencias de tracing; comprobación TypeScript aprobada.
- Navegación, pausa, movimiento reducido, gestos, responsive y fragmentos comprobados en Chromium de escritorio y móvil. Una tanda completa tuvo 24 aprobadas y 2 timeouts bajo carga concurrente; la repetición serial de navegación tuvo 16 aprobadas. No se presenta esa tanda completa como verde.
- PDF: comprobados recuentos de 13/14 páginas en ambos proyectos de navegador.
- Servidor de producción local: revisión general 200; página/PDF/medios privados inválidos 404 sin caché; vistas dev 404; optimización de imágenes privadas 400.
- 21 capturas de revisión en test-results/audit-final, más una captura de producción de Somos36 con imagen decodificada. Textos principales dentro del escenario y cero animaciones al pausar; vecinas sin animaciones en ejecución. Un gesto real de la tira móvil desplazó 0→59 px sin cambiar de escena.
- Métricas y capturas son locales. No se obtuvo una línea base fiable de tiempos, FPS ni Core Web Vitals. El primer intento de captura se cruzó con las ediciones; sus tiempos no se usan como comparativa.

## Pendientes técnicos y editoriales

1. Aprobar cifras, fotos, testimonios y mensajes reales antes de distribuir. La revisión pública sigue siendo accesible con el enlace y permanece noindex.
2. Proveer configuración y medios privados al build. Las credenciales son transferibles; la revocación en una instalación empaquetada requiere actualizar y desplegar la configuración. Los logs de plataforma requieren control de acceso/retención.
3. Repetir npm audit con acceso al registro: el endpoint falló por red; no se afirma ausencia de vulnerabilidades de dependencias.
4. Validar en dispositivos físicos Android/iOS y medir fluidez/LCP/INP con datos reales. No se ejecutaron Lighthouse ni un lector de pantalla completo.
5. El esquema gallery no tiene una galería genérica implementada: usar los slots photos y la evidencia de empresa que consumen las escenas existentes.

No se introdujeron servicios ni abstracciones para futuros usos. Se preservaron los cambios existentes del checkout; los metadatos Git se localizaron en .gitdata.
